最核心的抽象，其实就是 workflow 这个抽象。因为 workflow 把工作流程积累了下来，我可以写很多很多的工作流程，不断地去整合它们。这样一旦工作流程显性化，很多操作就好做了。

这个简直是太重要了！他终于解决了我最大的麻烦，就是怎么把这种工作习惯传递出去。现在终于可以传递出来了。

虽然它还有很多限制，比如说受到我们对于产物的定义的限制、各种操作工作工具的限制，但是已经足够用了。

我的助理拿着 AI 试了一下，说大部分流程能猜得出来，少数不行。那就证明这个程序还是非常重要的，这是意料之中的情况。

这个工作方法肯定有它的边界，但是，比如它套一个 PI 然后去把各种工作流程串起来，绝对是非常有用的。它可以很大程度上起到把流程注入进来的感觉，并且比 skill 要靠谱。

在想它可以跟 PI 的工具链对起来，或者跟其他各种各样的 Agent 工具对起来，以工具为单位去编排。

因为我们现在做的主要操作其实就是 read file, edit file，然后 run bash。对，就这个足够编排了。哪怕是其他一些工具，再复杂一点，无非就是增加一些 web search 之类的工具，我们完全可以编排。

核心的点就在于，我们每个步骤后面都放一个验证的方式，这样流程会更稳定一点。

而且最主要的是，错了之后，我们可以直接去编辑这个流程，这个流程也可以直接保存下来复用。这样的话，就比 skill 要靠谱很多。
