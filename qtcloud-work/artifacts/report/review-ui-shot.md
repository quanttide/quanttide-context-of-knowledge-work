## 精确版

写法：四段声明（输入 / 过程 / 输出 / 验收）逐条编号，每条后跟 `→` 写明它派生出哪条判据。**具体值——节名、上限、禁用词表、必带字段——只在声明里出现一次**；`rule` 判据的判法（`file`+`contains` / `run`）由声明里的落点、上限、词表机械生成，判据里不再抄一遍这些字面。`rule` 是能派生的；派不生的标 `agent` / `human` 并把判准写在该条声明里。

下面这份即替换进 `review-ui-shot.yaml` 的内容：四段块进 `description`，每条 `→` 按声明顺序收成该步的 `criteria`。`rule` 条目只给派生式（如 `由 O1 生成`），落地时由引擎造 `file` / `contains` / `run`；`agent` / `human` 条目判准就是它引用的那条声明。`{{material}}` 是新增占位（本次任务的截图），见「迁移」。

### 顶层

**输入**
- I1 读：本次任务那张界面截图 `{{material}}`（PNG，单张；落点 `<数据仓>/materials/`，起任务时放入）。`→ D1`（rule，由 I1 的落点生成 `path`；挂 impression）
- I2 读：`{{report}}` 当前内容，只为补写，不重写已定稿的节。`→ 并入 D5`
- I3 不读：其它任务的产物；不许读第二张图。`→ D3`（agent，判准＝I3：报告只引本任务的图与报告）

**过程**
- P1 步序＝`steps` 数组：impression → look → review → advise → conclude。`→ D2`（rule，引擎的 `next_step` 即判法，无字面）
- P2 工具白名单：只读写 `{{report}}` / `{{journal}}` / `{{log}}`；不跑会改工作区的命令。`→ D4`（agent，判准＝P2）

**输出**
- O1 落点 `{{report}}`；形态 Markdown；节表＝五步 O 声明的拼合，顺序即步序与声明序，共八节（倒金字塔：先判断、后枝节）。`→ D5`（rule，由 O1 的节表生成 `run`：八节标题行号严格递增；挂 conclude）

**验收**
- A1 八节齐、顺序如 O1。`→ D5`
- A2 每节内容满足该步的验收声明。`→ 各步判据即覆盖，不另立`

### 步 impression（human）

**输入**
- I1 读：同顶层 I1（同一张截图）。`→ D1`

**过程**
- P1 人写一句判断：整体感受，不是清点。`→ 并入 D8`
- P2 写进 `{{report}}` 的「第一眼」节。`→ 并入 D7`
- P3 记一笔：`qtcloud-work task <任务名> --done impression --note "第一眼：……"`。`→ D6`（rule，由 P3 的命令生成：`{{log}}` 里 impression 后有 ok 条目）

**输出**
- O1 落点 `{{report}}` 的「第一眼」节；形态一句判断；上限一句；必带字段无。`→ D7`（rule，由 O1 生成 `file`+`contains`）

**验收**
- A1 那句是判断（读得出整体感受），不是清点。`→ D8`（agent，判准即 A1）
- A2 日志里 impression 后有记录。`→ D6`

### 步 look（agent）

**输入**
- I1 读：同顶层 I1。`→ D1`

**过程**
- P1 逐区清点：对象、状态、动作、数字。`→ 并入 D10`

**输出**
- O1 落点 `{{report}}` 的「看到」节；形态分区清点；上限无；必带字段：位置、对象、状态。`→ D11`（rule，由 O1 生成 `file`+`contains`）

**验收**
- A1 满足 P3，且无编造。`→ D10`

### 步 review（agent）

**输入**
- I1 读：同顶层 I1。`→ D1`

**过程**
- P1 主诊断一句话说清最主要问题；与「第一眼」对照——一致说明理由，不一致说明为什么。`→ D13`（agent，判准即 P1）

- P5 禁忌：主诊断不许是清点；拿不准不许混进证据。`→ D14`（agent，判准即 P5）

**输出**
- O1 落点 `{{report}}` 的「主诊断」节。`→ D15`（rule，由 O1 生成 `file`+`contains`）
- O2 落点 `{{report}}` 的「证据」节；上限五处；必带字段：图上位置。`→ D16`（rule，存在性由 O2 生成）；`→ D19`（agent，上限与位置，判准＝O2；上限只此一处）

- O4 落点 `{{report}}` 的「拿不准」节。`→ D18`（rule，由 O4 生成）

**验收**
- A1 主诊断满足 P1。`→ D13`

- A3 满足 P5。`→ D14`

### 步 advise（agent）

**输入**
- I1 读：`{{report}}` 的「主诊断」与「证据」；不许凭空生成建议。`→ D20`（rule，由 I1 生成 `run`：进入 advise 时「主诊断」节在）

**过程**
- P1 按影响从大到小排序。`→ 并入 D22`
- P2 每条写清改哪里、改成什么、为什么；标影响面（安全 / 效率 / 辨识）与改动代价（小 / 中 / 大）。`→ 并入 D22`

**输出**
- O1 落点 `{{report}}` 的「建议」节；形态有序列表；上限无；必带字段：改哪里 / 改成什么 / 为什么、影响面、改动代价。`→ D21`（rule，存在性由 O1 生成）；`→ D22`（agent，必带字段与排序，判准＝O1）

**验收**
- A1 每条建议满足 O1。`→ D22`

### 步 conclude（agent）

**输入**
- I1 读：`{{report}}` 的「第一眼」与全部前节。`→ 并入 D5`

**过程**
- P1 开头三行依次写「是什么」「问题在哪」「先改什么」。`→ 并入 D24`
- P2 一句话复述这张图的问题，与「第一眼」对照。`→ 并入 D24`
- P3 列出仍拿不准的地方。`→ 并入 D23`
- P4 收口：等人拍板。`→ 并入 D25`

**输出**
- O1 落点 `{{report}}` 的「结论」节；形态：开头恰三行 + 复述一句 + 拿不准清单；上限：开头恰三行。`→ D23`（rule，存在性由 O1 生成）；`→ D24`（agent，三行顺序与复述对照，判准＝P1＋P2）

**验收**
- A1 八节齐、顺序如顶层 O1。`→ D5`
- A2 满足 P1、P2。`→ D24`
- A3 创始人拍板（哪些建议采纳）。`→ D25`（human，判准即 A3）

## 迁移

为让上面这份精确版真的生效，按「实现 → 规格 / 定义 → 用例」的顺序动五处。性质两分：**可并存**＝新增字段可选、缺省即老行为，老定义照读照跑；**破坏性**＝老定义读不进来。本方案全走可并存。

**落地顺序：** 3a/3b/3c（实现能读、能派生、能取材料）→ 2（规格追认）与 1（替换目标定义）→ 4（补用例）→ 其余工作流不动。

## 结论

**最缺什么：输入段的落点。** 五步都在读同一张界面截图，却没有一句说清图从哪来、放哪，于是「读的是同一张图」派不出判据，换图要改五处散文——其余缺口（节名与上限在散文和判据各写一遍、顶层无验收、「拿不准」没判据）都是这一处的派生症。

**判据条数：改动前 15 条，改动后 25 条。**

| | 改动前 | 改动后 |
|---|---|---|
| rule | 9 | 15 |
| agent | 5 | 9 |
| human | 1 | 1 |
| **合计** | **15** | **25** |

改动前那 15 条全部手写在 `criteria` 里，`description` 里没有四段声明，一条也「派」不出来；同一条意思（节名、五处上限、影响面与代价）在散文与判据各写一遍，改一处漏一处就误判。改动后 25 条（D1–D25）全部由四段声明派生，每条指得出出处；具体值——节名、上限、禁用词表、必带字段——各只出现一次。

**仍拿不准的：**

1. 「拿不准」算不算独立一节。顶层倒金字塔列七节（无「拿不准」），review 步却要写第八节；精确版按八节处理、配了 D18，但这是给工作流加了一节，它能不能并进「证据」的边缘，没有依据。
2. 四段声明压在 `description` 里还是升为字段。字段级 schema 没实现，本方案先压 `description`、`criteria` 显式保留；代价是「派生」只停在纸上，引擎仍读不到四段。
3. D2（步序）与 D4（工具白名单）算不算判据。前者判法就是引擎的 `next_step`，没有字面；后者只能靠智能体自查。计进了 25 条，但几乎不可证伪。
4. 禁用词表取值（混乱、不合理、糟糕、丑、差）是我依散文「这类词」补的，没有事实源。
5. 值不值得改。这是条人在环的截图评审工作流，为它动 schema（3a–3d）加补用例，收益要人拍板；好在本方案全走「可并存」，不动也不会坏。

**待拍板（哪些先改、哪些先不动）：** 建议先动 3a/3b/3c 与替换目标定义（加 `--material`、让 `{{material}}` 可展开、把四段声明读进来），规格与用例随后；其余 9 条在用的工作流一处不动。上述 5 条拿不准的，请一并定。
