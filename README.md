# quanttide-context-of-knowledge-work

量潮知识工作语境——知识工作领域的上下文背景与关联语境。

## 定位：驱动层

context 是知识工作系统的**驱动层**：系统（人或 AI）执行任何工作时读取的背景设定——当前在做什么、依据什么规则、处于哪个阶段、注意什么边界。它回答"带着什么上下文干活"。

与工作物家族的分工：

| 工作物 | 承担 | 问题 |
|---|---|---|
| **context（本仓库）** | 驱动 | **现在带着什么上下文干活？** |
| journal | 状态快照 | 这段时间发生了什么（按时间线索传递上下文） |
| 材料/档案 | 输入与沉淀 | 未处理的输入 / 已整理的知识 |
| 意图/洞察/路线图 | 方向与认知 | 为什么 / 学到了什么 / 先做什么 |

## 与 journal 的职责迁移

（2026-09-10 定）

- **journal 原承担的"驱动"职能移交给 context**：此前 journal 既是捕获入口又是事实源，AI/新会话要理解"现在怎么做"必须翻阅日志历史——驱动信息与时间线混在一起。
- **journal 转型为时间线索引**：按时间线索传递上下文——记录每个时间点发生了什么状态变化、哪份 context 生效、指向当时的工作物，本身不再承载驱动规则。
- 迁移方向：journal 里沉淀出的稳定规则（如整理移出惯例、分流规则）→ context；journal 保留一次性事件与状态变化记录。

## 内容形态

**无时态**：context 不是对某个时点的陈述，而是当前生效的驱动规则——因此**只保留最新版本**，不堆积历史（旧版本删除，变更过程由 journal 的时间线记录）。避免堆"乱七八糟的东西"。

按主题组织语境文档（驱动规则、当前阶段、工作约定），每篇独立可被系统加载。journal 按日期记录状态快照，指向生效中的 context。
