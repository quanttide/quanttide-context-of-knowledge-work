# 日志查询

## 需求

设计一个查询算法：我正在写某个情绪日记，想看看和写过的默认日记的某个片段相关，调取出来提醒我。

## 方案

**输入**：正在写的日记草稿（可以很短）
**输出**：相关的默认日志片段 + 出处坐标，提醒给写作者

### 索引（离线，一次性）

```
对 memory 默认日志的每篇：
  按 — 切会话段（一个段 = 一个检索单元）
  单元 = { path, line_start, line_end, date, text }
  向量化 text → 存向量 + 坐标
```

切段而不是切块——会话段是自然边界，命中就能说清「哪天、哪几行」。

### 查询（写日记时实时跑）

```
query = 当前草稿全文（不需要写完，几行就够）
q_vec = embed(query)

for 每个单元 u:
  score[u] = cosine(q_vec, u.vec)

按 score 降序，取 top-k（k=8，宁多勿漏）
```

草稿短也能跑——这正是走向量的理由：「这两天又不太顺利」没有可匹配的词，但向量知道它和「担心事情做不成」是一路的。

### 裁决（规则在出口，不在入口）

对 top-k 候选做三道筛：

```
1. 共振下限 τ₁：score < 0.55 → 丢（不相关）
2. 重复上限 τ₂：score > 0.92 → 标「已写过」而不是「提醒」（避免把日记里已有的再提醒一遍）
3. 聚线：同一情绪线的多个段归成一条
   同线 = 两段互相相似（段间 cosine > 0.7）
   输出：「这条情绪你在 9-05、9-16 都写过」——比列 5 个孤立段有用
```

τ₁/τ₂ 首轮跑完标定，**不回调参**（吸取上一轮融合权重的教训：先预注册，跑完再看）。

### 输出格式

```
你正在写的：「……草稿首句……」

可能相关（按相关度）：
1. [0.81] 9-16 ……「我感觉我最近又找不到那种代入感了」
   ↳ memory/default/2026-09-16.md:3-7
2. [0.74] 9-05 ……「搭建整体结构的过程之中，多多少少有点不想干」
   ↳ memory/default/journal/2026-09-05.md:11-14
   （这条和 1 是同一条情绪线）

已写过（不再提醒）：
- [0.94] 事业波动.md 全文
```

**坐标必须带**——这是 H3 的业务落地：写作者能点回去核对，AI 提炼时也能溯源。

### 评判

拿已有情绪日记倒查：把每篇日记的**首句**当查询，看它的源日志段排第几。指标就一个——**源段 top-3 命中率**。
