在想 code 和 devops 领域的边界是不是需要重新划分。

主要还是代码审计问题。这个还是比较偏向形式化检测，更接近 devops 的实践。但是 devops 直接集成会很重，所以需要语义层面能够检测。

code 全面转向 intent 驱动以后，代码审计变成了一个次要功能，应该考虑把代码质量检查作为 devops 工程的一部分，区分语义和形式，类似 write 和 docs 领域的关系。

我暂先按照新的定义去整理，但是估计整个软件工程、第二大脑里面应该还有很多旧的东西，要慢慢去分离。

这样 devops 的领域就不会只有发布信息，也可以有代码质量信息等等信息了，code 领域的信息也更干净，两边都合适。那么这个划分就是合理的。
