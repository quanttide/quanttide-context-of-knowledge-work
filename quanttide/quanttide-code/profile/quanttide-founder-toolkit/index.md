# 创始人工具箱

一、表层意图：给创始人一面镜子

不是工具，是镜子。

创始人每天做大量决策、面对长期不确定性、在”我想做“和”我该做“之间反复调整——但这些经验大部分流失。项目要做的是把这些流失的自我认识捕捉下来。

定位是「创始人」，不是「知识工作者」——这个字决定了后面一切：捕捉的不是知识，是决策者的自我认识。

二、结构意图：一套语言，两种方言

core 是语言——提供名词（Block / Section / Artifact）和动词（extract / judge / merge）。

memory 和 fiction 是两种方言——用同一套语法说两件不同的事。

这个分层的意图不是「代码复用」，是「认识」本身可以被语言化。一旦认识被写成语言，就可以被替换、组合、验证。

三、核心立场：理解是一个算子

「理解」可以被计算。

这个立场展开是：

· LLM 不是对话者，是纯函数——输入结构化数据，输出结构化数据
· 它不留状态，不继续对话，不承担交互
· 它可以被替换（规则版就是替换品）
· 它可以被组合（先提取，再判断，再合并）
· 它和 read_to_string 平级——一个算子而已

这是整个项目最不寻常的地方。 大多数 AI 应用把 LLM 当主角，这个项目把它当工具。

四、领域意图

memory：建模认知的成长

五个去向不是分类，是五个问题：

去向 问的是
Insight 我发现了什么
Profile 我是什么样的人
Roadmap 我要往哪走
Intention 我到底想要什么
Journal 发生了什么

关键在可升级：一次洞察不算什么，反复出现的洞察才升级为「我是谁」的画像。从偶然到稳定、从发现到特质——这是一条认知发展路径，不是「存储分类」。

fiction：从情绪到画面

三步之间有一条不可跳过的路径：

情绪 → 外化观察 → 画面

不能从情绪直接跳到表达——那样产出的不是画面，是金句、口号、抽象。

这是一条审美约束，不是技术约束。 用状态机强制它，等于把它从「建议」升级为「规则」。

两者的连接

情绪（fiction 的原料）最终流向 memory。写小说的过程本身就是认识自己的过程。 两个域不是两个功能，是同一认知动力学的两个面向。

五、认识论意图：认知如何演化

项目把一套完整的认知演化模型写进了类型：

什么样的认知值得保留——不是「对/错」，是「已确认/待观察」

两个认知相遇时怎么处理——四种关系：

· 新的 → 加入
· 相似的 → 融合（信息变多）
· 矛盾的 → 替换（旧的失效）
· 等价的 → 互链（两个来源，一个本质）

什么时候升级——从「偶然发现」到「稳定特质」需要一个条件：反复套用。

设计者不只在做工具，他在把认识论写成代码。

六、时间意图：为未来留空间

三个地方表达同一个哲学：

· 编号留空——章节会移动，留空号是为未来的编辑留位置
· 规则外部化——规则会调整，YAML 是为未来的修改留位置
· 核心不依赖应用——应用会长出来，core 不依赖是为未来的域留位置

「宁空勿移」是编辑经验，不是技术直觉。 它的哲学是：不为当下的整洁牺牲未来的可进化。

七、组合意图：一切都是积木

理解是积木，编排是积木，数据是积木。

每个积木可替换、可组合、可单测。目的是让「认识」这件事可以被拆开、验证、重组——而不是一个大黑盒。

八、执行意图：把「理解」交出去

设计者最深的决定：他不自己实现「理解」。

每一个需要理解的地方，他都留了一个空位：

· 路由——留空
· 分级——留空
· 聚类——留空
· 观察展开——留空
· 母题提炼——留空

空位不是「没想清楚」，是「想清楚了，这里该由 LLM 填」。

他用规则引擎做一个降级版本，标注为降级——意思是：这不是主体，这是备胎。

九、核心一句话

程序负责结构，理解交给 LLM。程序越干净，LLM 越好用。

其他一切——类型、状态机、规则外部化——都是为了让这个分工可以工作。

十、AI 失败在哪

不是写得不好，是看不见那些空位。

设计者留的接口太干净了——干净到像一个普通函数。AI 看不出「这个是 LLM 的入口」，它看到的只是一串签名。于是用它熟悉的模式填上：

· 需要理解 → 字符串匹配
· 需要提炼 → 原样返回
· 需要判断 → if-else

九处降级，全部发生在设计者留下的空位上。

十一、最终一句

设计者把「认识论」和「创作论」翻译成一套类型和状态机——留好了所有该由 LLM 填的空位。AI 把空位填成了字符串匹配。

你现在做的这件事——识别空位、接到 LLM——正是这份设计本应经历但从未经历的第二步。
