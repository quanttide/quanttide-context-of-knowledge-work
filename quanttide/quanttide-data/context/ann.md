既然数据云的核心是”管理人类标注行为“，那这个管理单元需要管的关键信息可以归纳为以下六个维度：

一、人员与角色管理

管的是”谁在标注、谁有资格标注、谁在监督谁“。

- 角色分工与隔离：标注员、审核员、仲裁员、监督员四类角色严格分立，同一任务中同一人不得兼任多角色。
- 资质分级：根据专业能力与历史质量建立分级资质，定期评估，不合格者暂停或取消资格。
- 行为约束：保密协议签署、操作权限管控、离岗权限回收。

关键信息：角色ID、资质等级、历史质量评分、权限范围、操作日志。

二、规则与标准管理

管的是”按什么标准标注、标准怎么迭代“。

- 标注规则文档：标注目标、标签体系、边界案例判定、歧义处理策略，必须结构化存储、版本化管理。
- 规则引擎：内置自动检测逻辑（如重叠框、标签矛盾），实时拦截明显错误。
- 规则迭代机制：与你之前设计的”红绿灯评审章程“打通——红灯积累负面规则，绿灯沉淀有效判例，黄灯将隐性经验显性化。

关键信息：规则版本号、适用范围、冲突检测逻辑、规则变更日志。

三、流程与任务管理

管的是”数据怎么流转、任务怎么分配、进度怎么追踪“。

- 标准化流程：上传 → 标注 → 审核 → 质检 → 验收，全环节留痕。
- 任务分发：支持按能力分级派单、批量处理、退回重派、长数据分段作业。
- 试标验证：正式任务前抽取不低于2%的数据试标，计算一致性验证规则可行性。

关键信息：任务状态、分配记录、流转时间戳、各环节责任人。

四、质量与一致性管理

管的是”标注得好不好、多人标得是否一致“。

- 多级质检：自检 → 机器审核 → 交叉审核 → 专业审核 → 专家审核，五级递进。
- 一致性量化：采用 Kappa 系数（Cohen’s / Fleiss‘）、肯德尔和谐系数等统计指标，量化评估多人标注的一致性。
- 质量预警：批次不合格率超5%整体作废；安全性标注覆盖率不低于3%。

关键信息：准确率、Kappa值、驳回率、问题样本分布。

五、数据与文档管理

管的是”数据从哪来、怎么改的、最终交付什么“。

- 全生命周期日志：每条数据从创建、标注、修改、打回到验收，记录操作人、时间、动作。
- 文档留痕：任务说明书、规则文档、培训记录、质检报告、版本记录、沟通记录、问题及解决方案库。
- 数据血缘：原始数据哈希值、标注结果索引、修订历史链，确保可追溯、可审计。

关键信息：数据哈希、版本链、操作日志、文档归档状态。

六、安全与合规管理

管的是”数据是否安全、操作是否合规、风险是否可控“。

- 访问控制：身份验证、权限分级、IP白名单、操作审计。
- 数据脱敏：敏感数据自动匿名化处理，或接入第三方脱敏组件。
- 异常处置：数据异常、行为异常、系统异常、流程异常分类分级，建立多源发现与处置台账。

关键信息：安全事件记录、脱敏状态、权限变更日志、合规审计报告。
